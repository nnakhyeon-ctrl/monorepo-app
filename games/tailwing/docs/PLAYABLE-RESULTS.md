# AIRZERO STRIKE 실제 전투·확장 결과

2026-10-19 기준. 사용자가 기존 4단계 범위를 실제 전투·1~3탄 검증 후 15탄 확장·협동 개발까지 확장했다. 이 문서가 현재 구현 상태의 기준이며 STAGE4-RESULTS와 UPGRADE-RESULTS는 이전 화면 작업 기록으로 보존한다. 스토어 등록·배포·유료 서비스 가입은 실행하지 않았다.

## 1~3탄 검증 기준과 밸런스

초기 30초 단일 보스 구조를 55초 단위 구간과 160~170초 보스 진입으로 바꿨다. 첫 무료 시뮬레이션이 실패해 그대로 확장하지 않고 수정했다. 적은 약 0.65초 먼저 공격을 예고하고 조준 방향을 고정한다. 화면 아래로 통과한 적은 기체 바로 옆에서 새 탄을 발사하지 않는다. 55초·110초 구간에는 살아 있는 기체의 장갑을 1 회복하며 화면에 정비 안내를 표시한다. 유료 소모품이나 추가 결제가 아니다.

`tool/campaign_probe.dart`는 동일 실제 엔진·무료 구성으로 제한 속도의 좌우 이동과 보호막을 사용한다. 결과: 1탄 249초/장갑3/4300점, 2탄 244초/장갑3/3800점, 3탄 218초/장갑3/2700점. 화면 내 최대 탄환 29~33개였다. 자동 회피 알고리즘의 결과이므로 초보자 난이도·손맛·발열·매출 근거로 사용하지 않는다. 15탄·탄당 3~5분은 초기 목표이며 사람의 테스트 후 조정한다.

확장 후 4/6/9/12탄에서 자동 회피가 실패해 편대 간격·탄 속도/배치를 보완했다. 최종 1~15탄 모두 무료 구성 성공, 212~296초(약3분32초~4분56초), 최대 동시 탄환35개다. 후반 완료 시간은 4~15탄 순서로 225/212/255/216/246/231/261/242/215/238/225/296초다. 이 고정 입력 정책/시드의 통과는 모든 플레이어·모든 기기의 통과율을 뜻하지 않는다.

무료 기체 장갑3·기본 조종사·자동 2연사·보호막으로 모든 작전에 진입할 수 있다. 유료 리온은 좁은 집중 사격/피해+20% 대신 장갑-1, 이든은 넓은 3방향/탄당 피해-25%와 장갑+1/보호막+0.5초다. 벡터도 속도/연사+15% 대신 장갑-1이다. 유료 선택이 무료 공략의 필수 조건이 되지 않도록 계속 조정한다. 최종 능력 수치는 출시 확정값이 아니다.

## 실행·검사

앱 경로는 `games/tailwing`다. PowerShell에서 루트의 VS Code F5 구성 ‘AIRZERO STRIKE · Android 전투’을 선택하거나 해당 앱 폴더에서 아래를 사용한다. Dart package `raikeopeu2026`, Android namespace `com.example.raikeopeu2026`, applicationId/Bundle ID `com.example.raikeopeu2026.dev`는 유지했다.

```powershell
flutter --suppress-analytics analyze --no-pub
flutter --suppress-analytics test --reporter expanded
dart run tool/campaign_probe.dart
flutter --suppress-analytics test integration_test/screen_flow_test.dart -d emulator-5554 --dart-define=AIRZERO_INTEGRATION=true --no-uninstall --reporter expanded
flutter --suppress-analytics run -d emulator-5554 -t lib/main.dart
```

현재 정적 분석 문제 없음, 호스트 검사 44개와 Android 네이티브 통합 검사 2개 통과. 첫 조작/무료 전투·보호막·화면 이동·유료 잠금·미연결 복원, 네이티브 파일 결과 저장/해금/재도전·앱 재생성 후 1~3탄 기록 복원을 확인했다. 결과 전이 검사는 격리된 가상 보스 종료 조건을 사용한 UI/실제 파일 검사이며, 전탄을 사람이 실시간 플레이한 기록은 아니다. iOS UI 조건 검사는 호스트 위젯 테스트이며 iOS 빌드/기기 검사가 아니다.

Android 검사 APK는 `AIRZERO_INTEGRATION=true`일 때만 debug에 `.integration` suffix를 붙인다. 일반 ID는 유지한다. Flutter 3.47.7 검사 도구는 시작 전 기존 APK에서 package ID를 보관한 뒤 종료 시 기본적으로 그 앱을 삭제한다. 일반/검사 APK를 같은 출력 경로에서 바꾸면 이전 ID를 정리할 수 있으므로 반드시 위의 `--no-uninstall` 옵션을 함께 사용한다. 로컬 SDK 소스로 이 동작을 확인했다. 가상 기기만 사용하며 운영 사용자 자료로 통합 검사를 실행하지 않는다. 정상 앱의 실제 기기 업데이트/기록/구매 권한 보존은 별도로 확인한다.

기기 기록은 applicationId/Bundle ID를 바꾸지 않는 앱 업데이트에서 유지하는 경로다. 두 사본은 앱 전용 `airzero_progress/progress_a.json`, `progress_b.json`이며 토큰·이메일·구매 권한은 넣지 않는다. 앱 삭제/데이터 지우기는 로컬 기록을 지운다. 서버 저장 완료로 표시하지 않는다. 파일 두 개 모두 손상되거나 더 최신 스키마이면 보존 모드로 전환하고 임의 초기화/덮어쓰기를 하지 않는다.

공식 의존성 `path_provider: 2.1.6`과 Android JNI 빌드 구성을 검토한 후 앱별 lockfile에 고정했다. 루트 Node 의존성·다른 앱은 변경하지 않았다. [공식 패키지](https://pub.dev/packages/path_provider), [공식 소스](https://github.com/flutter/packages/tree/main/packages/path_provider).

## 최종 실행 확인

- 정적 분석 문제 없음, 호스트 검사44개 통과. 마지막 서버 상태 순서/협동 변경 관련5개도 통과했고 최종 전체 검사44개를 다시 통과했다.
- Android 통합 검사2개 통과. 검사 전용 `.integration` ID와 `--no-uninstall`을 함께 사용한 최종 실행에서도 두 검사 통과, 일반 개발 앱 설치가 유지됐다.
- 일반 `lib/main.dart` debug APK 빌드·식별자 메타데이터 확인·`adb install -r` 업데이트·Activity 시작 성공. 가상 표식 파일이 검사 전/후·업데이트 후 동일한 해시로 유지됨을 확인하고 검사에서 만든 표식만 제거했다. 실제 사용자 기록/토큰/영수증 본문을 읽지 않았다. 이 표식 검사는 Android 내부 파일 유지 검사이며 모든 스키마/실기기 업그레이드·구매 권한 검증을 대신하지 않는다.
- 최종 일반 앱 첫 화면을 가상 기기에서 확인했다. 제목/기체/시작/작전 선택/장비/설정/하단 안내가 표시되고 배경 구름이 제목/버튼 영역 밖으로 그려지던 현상을 clip으로 수정했다. 화면 캡처는 공개 산출물에 복사하지 않았다. 에뮬레이터에는 일반 앱을 실행한 상태로 남겼다.
- 기존 `.vscode/settings.json`, 빈 `Untitled-1.txt`, 기존 키 아트2개 해시 동일. 앱 ID·Dart package 유지, 자동 commit/push·외부 공개 없음. VS Code F5 이름은 ‘AIRZERO STRIKE · Android 전투’다.
- 저장 경로 플러그인 빌드에 필요한 공식 Android Platform35·CMake3.22.1이 SDK 관리 경로에 설치됐다. JBR native-access/SDK XML 버전 경고는 빌드를 막지 않았고 보안 옵션을 낮춰 없애지 않았다.
- 문서66개·민감정보 패턴 검사 통과. 이번 범위에 루트 배포 CI·Terraform 실행은 해당하지 않으며 생략한 검사를 통과로 표시하지 않는다.

## 남은 검증

- 4~15탄의 난이도·시간·보스 차별화와 사람의 무료 공략, 모든 유료 조합의 장기 밸런스.
- 실기기 크기별 잘림·터치 지연·프레임 시간·발열·메모리·강제 종료·앱 업데이트 유지 검사. 에뮬레이터 결과로 실기기 완료를 대신하지 않는다.
- 실제 로그인/게스트 전환·두 기기 서버 저장·계정 삭제, 공식 구매/복원/환불/유예·서버 영속 중복 방지.
- 협동 인증·결과 정산·지연/패킷 손실/중도 이탈·Android↔iOS 두 실기기. 확인 전 첫 출시에서는 싱글을 우선하는 제안이며 최종 공개 범위는 사용자 결정이다.
