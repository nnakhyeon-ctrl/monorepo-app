# 테일윙 실제 앱 후속 확인 결과

2026-10-30 KST. 대상은 `games/tailwing` 한 앱이다. 기존 데이터/ID/서명 설정·무료/월간/연간 모델·구매 잠금을 유지했다. 로컬 구현/가상 앱 검사와 실제 서버/스토어/실기기를 구분한다. **11단계 최종 검증·최종 제출 준비 완료가 아니다.** 중단 당시 기록은 [체크포인트](TAILWING-FOLLOWUP-CHECKPOINT.md)에 보존한다.

현재 가능한 후속 구현/확인/안내를 정리했다. [파일·현재 소스·검사 증거 대조](tailwing/FOLLOWUP-LOCAL-CHECKS.json)·[현재 빌드/해시](tailwing/BUILDS.json)·[실제 화면20장](tailwing/index.html)을 저장했다. 추가 과금/배포/등록·실사용자 삭제 없이 소유한 가상 기기를 종료하고 멈춘다.

**고유 기술 `signature`는 무료 캐릭터 3종도 구독 전용**이다. 무료 3종에는 기본 사격·기본 보호막과 기존 기본 공격/장갑 특성이 있다. 검증된 월·연 구독은 전체 12종/고유 기술/기존 추가 콘텐츠를 이용한다. 연구소에서는 모든 종을 무기록으로 시험하지만 정상 구독 권한을 만들지 않는다.

**해적 곰·수달은 별도 캐릭터나 판매 스킨이 아니라 모루·누비의 기본 디자인**이다. 스킨 전환 기능/추가 SKU/새 구매 ID는 없다. 개구리의 `tw_chameleon`은 저장 호환용 ID이며 표시/그림/기술은 개구리다.

## 3. 발견 문제·수정·관련 검사

- **결과 화면에서 기술 상태 잔류:** 승리/패배/시간 초과 때 더 이상 step이 오지 않아 active·비콘·수집탄·잔상·둔화가 남던 경로를 수정했다. 터미널 전환에서 정리하며 종료 후 늦은 곰 반격을 만들지 않는다.
- **갑판 종료 내구/교란 참조 잔류:** 자연 종료 시 내구0·교란 대상 참조 제거. pause는 시간 보존, 장착 변경/만료 시 기존 효과 정리, 새 스테이지/재도전은 새 엔진을 사용한다. 피해/지속/대기/판매 구성은 바꾸지 않았다.
- 관련5파일 **64개 통과**: `animal_lifecycle_test`, `animal_roster_test`, `campaign_test`, `battle_engine_test`, `battle_flow_test`. 무료15탄 모델 진행·작은 화면/큰 글자·실제 충돌 결과/재도전 포함. 최초 실패/시험 경로 오류 이력은 체크포인트에 보존했다.
- 전체 정적 분석 문제 없음(35.5초). 이후 연구소 스크롤 검사/카탈로그 도구 대상 분석도 문제 없음. 서버 코드는 이번 후속에서 변경하지 않아 기존21개 단위/43개 demo 이력을 반복 검사로 바꾸지 않았다.
- Android 후속 첫 실행은 **1통과/연구소1실패**였다. 앱 기술 오류가 아니라 lazy ListView 바깥 버튼을 찾지 못한 검사 코드였다. 스크롤 후 위젯을 만들도록 보완하고 연구소만 **1통과(27초)**로 재검사했다. 긴 무료1탄 검사는 반복하지 않았다. [첫 결과](tailwing/NATIVE-FOLLOWUP.json)·[연구소 재검사](tailwing/NATIVE-LAB-RECHECK.json).

기존 A/B·게스트/탈퇴·구매 검증의 통과/미검증 기록은 유지한다. 위64개를 이번에 모든 인증/스토어 실연동까지 검사한 것으로 해석하지 않는다. 시험용 `.integration` 서명 불일치에 따른 별도 가상 시험 앱 재설치 이력도 체크포인트에 남겼다. 일반 앱/실사용자 자료는 대상이 아니다.

## 4. 가상 기기 시작 지연·성능

새 일반 개발 APK의 독립 설치(-r,제거/초기화 없음)·cold 시작3회·warm 재실행·제한 생존은 [시작 검사](tailwing/STARTUP-CHECK.json)에 기록했다. cold3회는 각각 **8239/5083/3627ms**,모두 `Status ok`,매회5초/15초·마지막 추가30초 뒤에도 프로세스 생존. warm 대기10ms였고 이전 PID 소실은 이번에 재현하지 못했다. 과거 원인은 **미확정**이다. exit reason과 subreason을 구분했으며 USER REQUESTED/FORCE STOP 이력에는 이번 통제 재시작도 포함되므로 예전 앱 충돌 증거로 사용하지 않는다. 과거 실행 기록은 [빌드 이력](tailwing/BUILD-HISTORY.json)이다.

분리 기준: APK 빌드/설치 시간, Android Activity 시작 시간, 이후 프로세스 생존, 실제 Flutter 기능 실행, 호스트 메모리, 물리 기기 성능을 각각 본다. 이전 호스트는 약16GB/VM 시작 전 가용3.38GB, native 중 약0.77~1.00GB 관찰로 자원 압박 가능성이 있다. 이 수치만으로 앱 원인을 배제하지 않는다. API37/2GB/4core VM은 실기기가 아니며 debug 프레임 측정/테스트 pump 지연은60fps 인증이 아니다. 원인 확인에 없는 로그를 추측하거나 일반 앱을 지워 해결하지 않는다.

이번 독립 시작 검사 중에는 호스트 가용 메모리가 약0.15GB까지 낮았다. 환경 자원 압박을 관찰한 사실과 지연의 확정 원인을 구분한다. Activity 시작/프로세스 생존만으로 Flutter 모든 화면/장기 안정성·실기기 발열/입력 지연을 통과시킨 것은 아니다. 시작 검사 뒤 소유 VM을 종료했다.

## 7. 11·12단계 갱신 경계

11단계는 종료 상태 정리의 관련 검사와 위 native/시작 확인 범위만 갱신한다. 실인증/결제/공개 삭제·iOS/실기기·보안 경고의 최종 통과는 아니다. 12단계는 현재 소스의 미서명 release 검사 파일·해시/소스 지문/제한 정적 검사와 새6장 검토 갤러리를 갱신한다. 제출용 AAB/IPA·새 브랜드 아이콘/native 시작 화면·스토어 RGB 캡처/소개·확정 정책/운영 URL·심사용 계정 방법은 계속 남는다. 설정 후 해당 기능 단계→11단계 영향 검사→12단계 파일/자료 재생성 순서다. 비용/배포/스토어 공개·실사용자 삭제·commit/push는 하지 않는다.

현재 release 빌드는161.9초 성공,0.1.0+1/기존 일반 ID 유지. [458항목 제한 정적 검사](tailwing/APK-INSPECTION.json)의 권한/백업/cleartext·시험 표식·ZIP/ELF16KB 조건은 통과했다. **미서명·설치/제출 불가**이며 이 APK의 실행/16KB 실기기·실서버/스토어는 검사하지 않았다. 이전 [빌드](tailwing/BUILD-HISTORY.json)·[APK 검사](tailwing/APK-INSPECTION-HISTORY.json)도 보존한다.
