# 13단계 계속 편집 — 출시 확정 아님

사용자는 캐릭터 그래픽·스킬·기능을 만족할 때까지 계속 수정할 예정이다. 앱은 계속 편집할 수 있으며 제출 후보를 동결하거나 자동 공개하지 않는다. 현재 구체적인 새 기능/밸런스 요청이 없으므로 검색 기능·임의 스킬 수치·새 유료 상품은 추가하지 않았다.

다음 요청에는 바꿀 대상(예: 토끼 외형/거북이 기술/홈 구성)과 원하는 동작·외형을 전달하면 된다. 수치나 유료 범위 변경이 명시되지 않았다면 기존 값/기록/앱 ID·선택 ID·잠금을 유지한다.

| 변경 대상 | 편집 위치 | 영향 확인 |
|---|---|---|
| 캐릭터/기체 그림 | `assets/tailwing/`, `lib/game/animal_roster.dart`, 자산 로더 | 12종 유지·선택/탑승 일치·작은 화면·디코드 메모리/경계 |
| 스킬/방패 | `animal_combat.dart`, `animal_roster.dart`, `deck_status.dart`, `battle_hud.dart` | 판정/시작·종료/내구·수치·피격·구매/만료 경계 |
| 홈/선택 화면 | `lib/features/home.dart`, `hangar.dart` | 가림·280/320/396 폭/큰 글자·선택 전환·출격/잠금 |
| 계정/구독/기록 | `lib/security/`, `server/firebase/`, 저장 코드 | 가상 A/B 경계·회수/실패·실서비스/스토어 관련 기능 단계 |
| 앱/스토어 아이콘 후보 | 이 폴더 `graphics/*.svg` | 후보 렌더→선택→native 교체→플랫폼/런처/마스크 검증 |

캐릭터/기술 수정 후 관련 Flutter 검사를 실행하고, 서버 변경이면 서버 단위/demo 검사를 추가한다. 11단계에서 데이터 흐름·로그·권한·미설정 기본 거부와 실제 기능 경계를 대조한다. 12단계에서 새 소스 지문·버전/서명/빌드 SHA·실행/화면·정책·소개를 다시 만든다. 소스/자산 추가를 감지한 해시 검사 실패를 무시하지 않는다.

그래픽 후보를 렌더하는 도구는 SVG만 PNG로 내보내며 앱 native 아이콘을 자동 교체하지 않는다. 예전 캡처와 새 아이콘을 혼합해 최종 출시 빌드라고 표시하지 않는다. 현재 자료의 편집/검증은 Google Play 게시 요청이나 제출 승인을 뜻하지 않는다.

정책 HTML의 직접 수정은 PAGE-GENERATION.json으로 감지해 생성기가 덮어쓰지 않도록 보호합니다. 그래픽의 icon-master.svg/feature-master.svg가 편집 원본이며 iOS SVG/PNG는 재생성되는 파생 파일입니다.
