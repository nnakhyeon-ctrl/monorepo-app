## 실제 저장 상태

- 프로젝트 지침·README/ROADMAP·현재 홈/격납고/전투 렌더러·자산 로더/HUD와 기존 자산을 읽었다. 최신 승인된 작업 범위는 아래5개이며 이전 일반적인 예시가 아니다.
- 내장 imagegen 스킬로 기존 자체 초상만 편집한 **토끼·거북이 초상 시안2장**을 확보했다. [정확한 프롬프트/참조 원본/생성 원본 경로/크기/PNG 형식/SHA](tailwing/design-pass-01/ART-JOBS.json). 원본은 생성 도구 위치에 그대로 보존하고 프로젝트에 사본을 저장했다.
- 시안: [토끼](tailwing/design-pass-01/rabbit-portrait-draft.png),[거북이](tailwing/design-pass-01/turtle-portrait-draft.png). 토끼는 둥근 볼/크림·민트 비행복/귀 통신 장치,거북이는 둥근 분할 등껍질/청록 패널/소형 추진 모듈 방향이다. **최종 채택/게임 적용 완료가 아니다.** 기술적 alpha/표시 크기·작은 화면 품질은 재개 후 확인한다.
- 병렬로 진행하던2개 생성 요청을 정리했으며 두 번째 이미지도 종료 시점에 반환돼 함께 저장했다. 추가 생성은 시작하지 않았다. 실행 중인 앱 빌드/검사/가상 기기는 이번 디자인 단위에서 시작하지 않았다.
- **lib/·현재 assets/·게임 수치·앱 ID·저장/계정/보유 권한·구매 잠금·기존 APK는 아직 바꾸지 않았다.** 새 초상은 docs 안의 미적용 시안이다. 이번 단위에서 홈/선택/전투의 새 화면 캡처·성능/실기기 검사를 수행했다고 표시하지 않는다. 이전 [후속 결과](TAILWING-FOLLOWUP-RESULTS.md)의 통과/실패/미검증은 그대로다.

## 승인된 수정 범위와 다음 순서

1. **홈:** TAILWING 로고·현재 선택 동물/탑승 기체 중심. 얼굴/기체와 문구/버튼을 분리하고 ‘출격’을 쉽게 찾게 한다. 현재 `FlightArtwork`의 작은 초상/문구가 이미지 위에 겹치고 다른 프레임 선택 시 동물 대신 프레임 그림만 보일 수 있으므로 실제 선택을 유지하는 표현을 검토한다. 기존 startGame/선택/기록·보유 권한 경계 유지.
2. **토끼·거북이만 우선 디자인:** 전체 제작 범위는 초상2·실제 전투용 탑승 기체2·홈용 탑승 이미지2=6장. 현재 초상 시안2장만 저장했고 **기체/홈4장은 미제작**. 동일한 옷/통신/등껍질 특징을 실제 탑승 그림에 맞춘다. 기체/조종사 같은 방향,탑뷰 기수 위/후방 추진 아래 유지. 다른 작품 얼굴/장비/연출 복제 안 함. 기존 파일 보존·새 버전 파일로 연결한다.
3. **선택 화면:**12종 유지. 현재 캐릭터는 대체로1열이고 스킬만 조건부2열이다. 세로 기본3열을 검토하되 좁은 화면/큰 글자는2열/1열로 안전하게 대응한다. 카드의 선택/잠금을 문구+체크/잠금 형태로 구분한다. 선택한 캐릭터 큰 초상·탑승 기체·기술·무료/구독 상태를 함께 보여준다. 미보유 캐릭터 설명 미리보기와 실제 선택/장착을 구분하고 잠금을 우회하지 않는다.
4. **거북이 방패 표현:** 현재 판정/지속/대기/내구를 먼저 대조하고 변경하지 않는다. 시작/작동/소진/시간 종료를 시각적으로 구분하고 실제 남은 시간·내구를 표시한다. 현재는 일반 HUD에 남은 기술 시간만 있고 갑판 내구는 주로 연구소 텍스트에 있다. `rendering.dart`의 기존 영역 표시는 옅어 가독성을 개선할 여지가 있다. 방어 범위/차단 가능한 일반탄·측후방/보스탄 제외·피격 반경은 유지한다.
5. **전투·화질:** 적탄은 현재 주황 원형/윤곽,아군은 긴 민트 탄이다. 작은 화면에서 진행 방향을 읽을 짧은 꼬리/방향 표시·대비를 검토한다. 판정·탄속/패턴·효과 피해값은 변경하지 않는다. 발광/파괴 효과가 위험 탄/피격 중심을 가리지 않도록 순서/상한 유지.

## 확인한 자산/표시 기반

기존 런타임 초상/기체는 주로 폭512,원본 생성 파일은 별도 보존돼 있다. 전투 `preparePilot`은 폭256 디코드,홈 hero는512 cacheWidth,초상 모션은256,무료 작은 선택은128을 사용한다. 배경은720. 출력 확대 문제와 원본 자체 품질을 구분해야 하며 단순 보간 확대를 새 고해상도 제작으로 표시하지 않는다. 새 시안 원본의 실제 크기는 ART-JOBS.json에 기록했다. 새 자산 저장/디코드 크기는 실제 표시와 DPR·메모리·로딩을 보고 정한다. 나머지10종 자산과 밸런스는 이번에 임의 재제작/변경하지 않는다.

## 재개 후 검증·전후 비교

- UI 변경 전 현재 앱의 홈/선택/거북이 전투 기준 캡처를 먼저 확보한다. 기존 실제20장 자료는 보존하되 정확한 현재 선택 화면 기준이 없으면 새 기준 캡처가 필요하다.
- 두 캐릭터의 얼굴/기체가 문구나 버튼에 가려지지 않는지,홈 출격 버튼 가시성/중복 출격 차단·선택 전환·3열/좁은 화면/글자 확대·잠금·무료3종/구독 범위를 검사한다.
- 방패 시작/남은 시간/내구 감소·소진/시간 종료·캐릭터 전환/재도전 초기화와 기존 방어 대상/범위의 불변을 검사한다. 수치는 승인 없이 바꾸지 않는다.
- 실제 렌더 자산 규격/alpha/로딩·메모리·프레임 영향을 기록한다. 개발용 가상 검사와 실기기 미검증을 구분한다. 필요한 새 이미지와 미제작/임시 시안은 완료로 표시하지 않는다.
- 전후 실제 홈·선택·전투 비교와 실행 방법,변경/검증/남은 범위를 문서에 저장한다. 변경 영향의11단계 검사·12단계 파일/캡처/소개 갱신을 기록하고,이번 결과를 본 뒤 나머지 캐릭터 방향을 사용자와 정한다.

이번 단위의 제출 파일 확정·스토어 등록/배포·과금 전환·실제 청구·실사용자 자료 삭제·commit/push는 하지 않았다. 기존 미연결 서버/로그인/스토어·공개 삭제 웹·Apple/iOS·실기기·보안 경고5개와 구매 잠금은 유지한다. **사용자가 재개를 요청할 때까지 중단한다.**
