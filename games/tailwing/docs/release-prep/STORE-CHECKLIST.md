# 스토어 직접 등록·시험 확인표 — 제출 보류

2026-10-29. 이 표는 사용자가 직접 할 일이다. 콘솔 생성/등록·업로드·테스트 배포·심사/공개를 실행하지 않았다. 체크되지 않은 항목은 완료가 아니다. 미정 값·가격·URL·새 서명 키를 대신 정하지 않는다.

## 먼저 필요한 공통 조건

- [ ] [첫 Firebase 화면 확인](../EXTERNAL-SETUP-ORDER.md): 기존 프로젝트/앱 ID·현재 개발 지문·Spark를 읽기만 하고 일치 확인. 서비스 계정 JSON 다운로드/과금 전환 없음.
- [ ] 전용 개발 서버·규칙/IAM/App Check·Secrets·세션/메일/공급자 검증을 실제 적용할 방법 결정. 현재 Functions 배포의 비용 조건은 무료 유지와 충돌하므로 대기. 무료 대안도 별도 구조·보안 검토 없이 바꾸지 않음.
- [ ] 7·8·9단계 이메일·소셜 재인증/취소·A/B/게스트·로그아웃·탈퇴/재시도/차단을 본인 개발 계정과 실제 서버에서 확인. 이메일 일치 자동 병합 안 함.
- [ ] 10단계 같은 혜택 월/연 상품 ID7개·판매 국가/가격·정당한 구매 복구/보관·월↔연 변경/제공 불가 거래 정책 확정. `BILLING-SETUP.md` 필드대로 준비하고 실제 테스트 전 구매 잠금 유지.
- [ ] 공개 HTTPS 지원·개인정보·약관·삭제 URL4개와 실제 접수/처리 경로. 정적 안내만으로 웹 본인 확인/삭제 완료 처리하지 않음.
- [ ] 운영자/개발자 케일의 법적 표시·연락처·개인정보 처리 지역/위탁/국외 이전·항목별 보관/예외/처리 기한·권리 행사를 확정. 불필요한 실제 개인정보를 저장소에 넣지 않음.
- [ ] SDK 실제 초기화/네트워크 전송·오류 로그·기기/서버 백업·삭제 후 잔존과 개인정보 문구 대조. '수집 없음'을 임의 선택하지 않음.
- [ ] Android/iOS 실기기에서 조작·성능/발열·입력 반응·글자 확대/읽기·키보드/자동완성·네트워크 거절/재시도·저장/업데이트 검사. 현재 가상 검사와 구분.
- [ ] 개발 의존성 보안 경고5개에 대한 공식 호환 수정 또는 근거 있는 위험 처리/재검증. 개발 도구라는 이유로 생략하지 않음.

## Google Play — 사용자 콘솔 입력 순서

1. [Play Console](https://play.google.com/console)에서 **기존 앱**을 선택한다. 앱 ID·앱 서명/업로드 키 지문·현재 versionCode와 소유권을 대조한다. 현재 소스 ID는 `com.example.raikeopeu2026.dev`, 버전 `0.1.0+1`이며 임의 변경하지 않았다. 기존 앱이 없거나 개발용 ID를 출시용으로 쓸지 미정이면 생성/업로드 전에 확정한다. 계정 가입/결제는 이번 작업에서 안 한다.
2. 스토어 설정/기본 스토어 등록정보: 이름·언어·짧은/상세 설명, 지원 연락처·웹사이트, 개인정보 HTTPS URL을 입력할 준비. [문구 후보](STORE-COPY.md)는 미연결 기능을 확정 문구로 바꾸지 않는다.
3. 그래픽: `graphics/play-icon-512.png`, `play-feature-1024x500.png`, `screenshots/android/`의 RGB4장. `raw/`·AI 배너를 실제 플레이 스크린샷으로 올리지 않는다. 실제 출시 빌드가 바뀌면 재촬영한다.
4. 앱 콘텐츠/정책: 광고 없음·타깃 연령/콘텐츠 등급·Data safety·계정 생성/삭제 경로·앱 접근 권한을 실제 SDK/기능대로 작성. 공개 삭제 주소는 재설치 없이 본인 확인/접수/처리 가능한 경로여야 한다. 계정이 필요한 심사 기능에는 전용 접근 계정/단계와 공급자 로그인 제약을 사용자 관리 보안 경로로 전달한다. 게스트 접근만으로 계정/유료 기능 심사 접근을 대체하지 않는다.
5. 수익 창출 → 구독: 기존 확정 subscription ID, monthly/annual base plan ID, 같은 혜택·국가/현지 총액/주기·갱신 조건. ID 미정이면 등록하지 않는다. [결제 설정표](../BILLING-SETUP.md)의 서버 허용 목록·내부 ID 귀속·알림/IAM/공식 재조회와 연결한다.
6. 설정 → 라이선스 테스트의 본인 개발 계정·테스트 트랙 테스터를 준비한다. 사용자가 서명 AAB를 직접 올려 테스트에 배포한 뒤 **라이선스 테스트 결제수단**인지 매회 확인한다. 일반 카드/실제 금액 화면이면 중단한다. 구매/복원·PENDING·취소/실패·중복·만료/환불·acknowledge·RTDN/역순/누락을 실제 서버와 확인한다.
7. 서명 AAB/빌드 번호·배포된 앱 서명 지문과 로그인/App Check/카카오 키 해시 대조, Android16/API36 및16KB 환경 검증, 실제 재설치/업데이트·계정 분리 검사가 끝난 뒤 수동 심사 절차를 판단한다. 현재는 이 단계 진입 보류다.

## Apple — 현재 멤버십·장비 대기

1. [Apple Developer 계정](https://developer.apple.com/account) 로그인만 완료, 유료 멤버십/Team 없음. **신규 유료 가입을 하지 않는다.** 현재 무료 조건으로 App Store 배포/Sign in with Apple 실연동/StoreKit Sandbox를 완료했다고 할 수 없다.
2. 사용자가 별도로 조건을 준비한 뒤 Mac·지원 Xcode/SDK·기존 Bundle ID/Team/capability·서명/프로비저닝을 대조한다. Apple 토큰/키는 서버에만, 실제 암호·인증서는 채팅/저장소에 넣지 않는다.
3. [App Store Connect](https://appstoreconnect.apple.com) 기존 앱에서 이름·Bundle·SKU/버전·지원/개인정보 URL·개인정보 공개/등급·앱 심사 접근 방법을 확인한다. 신규 앱/상품 생성과 업로드는 사용자 직접이다.
4. 동일 혜택 subscription group·월/연 product ID·지역 가격/주기·현지 이용 조건·서버 API/Notifications V2·Sandbox 본인 테스터를 연결한다. 상품 ID 미정이면 등록하지 않는다. Sandbox인지 확인하고 실제 청구를 하지 않는다.
5. Apple 로그인/철회·A/B/게스트·탈퇴·StoreKit 구매/복원·미완료 거래/finish·갱신·만료/환불·서버 알림과 실제 iPhone 전투/성능/재시작을 검사한다. iOS 원본 캡처·아이콘/Privacy Manifest·Archive/IPA 서명·실행을 검증한다. Android 통과로 대신하지 않는다.

## 수정 후 복귀

인증/계정은 7·8·9단계, 결제는10단계, 게임/저장은 해당 기능 단계에서 수정 → 11단계 변경 영향/개인정보/권한/실기기 재검증 → 12단계 새 소스 지문·빌드/서명/SHA·자료/문구 재생성 순서다. 통과한 전체 검사를 무조건 반복하지 않되 영향을 받는 증거는 갱신한다. 로컬 기능·서명 파일·공식 테스트·심사/공개를 각각 기록한다.
