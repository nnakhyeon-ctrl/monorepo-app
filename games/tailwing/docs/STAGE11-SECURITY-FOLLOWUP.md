### 배포 앱·서버에 미치는 영향

- 위 설치 노드는 모두 lockfile의 `dev:true`다. Flutter APK는 이 Node CLI를 실행하지 않고 선언된 Flutter 자산/네이티브 플러그인을 포함한다. 이 **두 Node 권고가 모바일 실행 코드에 같은 형태로 포함됐다는 근거는 없다**. 모바일 전체 의존성의 무결함/취약점 부재 선언은 아니다.
- 서버의 `--omit=dev` 감사에서는 경고0이다. 실제 원격 서버를 배포/검증한 것은 아니며 잘못된 배포 패키징으로 개발 도구까지 운영에 넣지 않아야 한다. 원격 빌드/CI·운영 최소 설치와 접근 제어는 배포 전 별도 확인한다.
- 개발 도구도 실제 권한/파일·네트워크에 접근할 수 있으므로 개발 전용이라는 이유로 무시하지 않는다. 해결되지 않은 경고는 최종 보안 대기로 유지한다.

## 안전한 수정 가능성 확인

1. `npm audit fix --dry-run --ignore-scripts --json`: **추가0·제거0·변경0**, 경고5 유지. 실제 의존성/lockfile 변경 없음.
2. 같은 major의 공식 gaxios6·pubsub5 최신과 firebase-tools15.34.1 메타데이터를 비교했다. 앞 표의 취약 간접 버전 범위를 그대로 요구한다.
3. 감사 도구의 전체 수정 제안은 firebase-tools14.23.0으로의 **major downgrade**다. 현재15.x 기능·에뮬레이터/권한 동작을 보존하는 검증이 없으므로 적용하지 않았다. 15.34.1도 자동 설치하지 않았다. [공식15.34.1 변경 사항](https://github.com/firebase/firebase-tools/releases/tag/v15.34.1).
4. 이전 `fast-uri 3.1.9` 패치는 그대로 유지했다. 경고 숨김·`--force`·임의 패키지 파일 수정·강제 override를 추가하지 않았다.

현재 확인한 호환 범위 안에서는 경고를 없애는 안전한 패치가 발견되지 않았다. 대응은 공식 상위 패치 확인→설치 스크립트/lock 변경 검토→단위/가상 API·실제 사용하는 emulator 경로만 재검증→새 전체/production 감사 기록 순서다. 지원 major 이전이 필요하면 해당 변경만 별도 비교하고 원격 배포/실계정 없이 검증한다.

기존 runner는 demo 프로젝트/loopback·가상 입력·상속 환경 허용 목록·CLI telemetry 비활성을 사용한다. 외부에 에뮬레이터를 공개하거나 실제 서비스 자격증명을 넣지 않는다. 이 운영 제한은 취약 코드 패치 자체를 대신하지 않는다.
