# 비용 가정과 결정 기록

7단계는 기존 Firebase 선택을 유지해 로컬 이메일 흐름만 검사했다. 새 클라우드 프로젝트/과금 플랜/Identity Platform/reCAPTCHA/메일 업체에 가입하지 않았다. 서버 메일 제한의 Firestore 읽기/쓰기·Secret Manager·공급자 메일/인증/App Check 호출 비용도 운영 산정에 포함해야 한다. 실제 비용/처리 위치와 외부 설정은 [7단계 결과](EMAIL-AUTH-RESULTS.md)에 구분한다.

2026-10-19 6단계는 로컬 demo Auth/Firestore/Functions로 검사했고 실제 과금 플랜/운영 리소스는 만들지 않았다. 서울 asia-northeast3는 DB/Functions 지원 후보이며 사용자 최종 선택 전이다. Firebase Auth는 미국에서 처리하므로 국내 DB 후보와 동일한 위치로 표시하지 않는다. Functions의 Blaze 준비·DB/네트워크/빌드/로그 비용과 운영 전 외부 설정은 [6단계 결과](AUTH-BACKEND-RESULTS.md)에 구분했다. [Firebase 공식 가격](https://firebase.google.com/pricing), [위치/개인정보](https://firebase.google.com/support/privacy).

## 사용자 결정

| 항목 | 확정 내용 |
|---|---|
| 앱 목적 | 신규 비행 슈팅. P-38 기반 기체·로봇 변신·폭탄 |
| 개선 방향 | 플레이 재화 기반 영구 성장, 기체별 개성, 읽을 수 있는 현대 탄막·작은 중심 판정 |
| 그래픽 참고 | 첨부 이미지의 대형 보스·편대·숲을 바탕으로 새 아트/가독성/기능 개선 |
| 원본 프로젝트 | 없음. 특정 원작 코드·자산을 업그레이드하는 작업이 아님 |
| 유료 모델 | 최신 요청: 기본 무료 + 추가 기체/스킬/캐릭터/특수 장비/강화 효과 월간·연간 구독. 두 기간 혜택 동일, 가격 미정 |
| 저장 | 2026-10-18 변경: 계정별 서버 저장·다른 휴대폰 이어하기, 기기 캐시/대기열·기기 설정 분리 |
| 호스팅 | Cloudflar 입력을 Cloudflare Pages로 해석한 계획. 서비스 가입/공개 안 함 |

가격은 아직 정하지 않았다. 설치/기본 플레이는 무료이며 월간·연간 프리미엄 구독을 선택했다. 영구 능력치 재화는 플레이 획득이며 실물 금전/환전/추가 결제를 추가하지 않는다. 매출·다운로드 수를 보장하지 않는다.

## 기술 선택과 유지비

Firebase Authentication + 앱별 Functions/Firestore 구매 원장을 선택한 이유는 Flutter의 이메일·Google/Apple 인증, custom token을 통한 Kakao 연결, 로컬 인증/DB/함수 에뮬레이터를 한 흐름으로 검증하기 위해서다. Supabase 같은 다른 관리형 인증이나 별도 상시 서버도 가능하지만 지금 이중 백엔드를 도입하지 않는다. Firebase 사용을 선택했다고 운영 프로젝트·Blaze 과금 플랜을 대신 만들거나 결제하지 않는다.

| 비용 구분 | 증가 요인·가정 | 현재 결정 |
|---|---|---|
| 인증 | 실제 월간 사용자·인증 방식·Identity Platform 선택·메일 제한 | 이메일/소셜 최소 기능. SMS·불필요한 MFA/분석 SDK 추가 없음 |
| 서버 검증/저장 | 호출 수·실행 시간/메모리·외부 API·네트워크·빌드/이미지 보관 | 구매/복원/철회와 체크포인트 저장/복구·충돌 검증. 매 프레임/탄환 서버 호출은 하지 않음 |
| DB | 계정/구매·게임 프로필·정산/세션의 읽기·쓰기·저장·백업/삭제 | 진행·성장·재화를 서버로 동기화하므로 기존 기기 전용 안보다 사용량 증가. 체크포인트/스냅샷 크기와 재시도·오래된 자료 정리 설계 |
| 비밀·알림 | Secret Manager 버전/접근·Pub/Sub·로그 저장 | 최소 권한·원본 비밀/토큰 로그 금지·불필요한 상시 요청 축소 |
| 정적 호스팅 | Cloudflare 플랜·요청/빌드·사용자 도메인/부가 기능 | 안내 문서용. 함수/스토리지 유료 기능은 자동 활성화 안 함 |
| 스토어 | 개발자 프로그램·거래 수수료·세금·국가/프로그램별 조건 | 실제 가입/정산은 사용자. 가격 결정 전에 적용 조건 확인 |
| 제작·운영 | 새 스프라이트/음악/폰트 라이선스, Mac/iOS 테스트, OS/SDK 업데이트·복원/환불 지원 | 첫 출시 기체/분량을 제한한 제안, 앱 판매 후에도 유지비가 남음 |
| AI/API·광고 | 현재 요구에 없음 | 도입/호출/비용 없음으로 계획. SDK 실제 도입 여부는 이후 검증 |

실험용 산정식은 월 서버비 ≈ 인증 과금 대상 사용량 + 구매/로그인/저장/삭제 호출 × 실행 단가 + DB 읽기/쓰기/삭제 × 단가 + 저장/백업/네트워크/알림/비밀/빌드 보관이다. 클라우드 저장과 정산·충돌 처리도 비용에 포함한다. 무료 사용자에게도 서버 기록 유지비가 발생한다. 구독 전환율·월간/연간 구성·해지율·스토어 수수료·콘텐츠 제작/검수 비용을 가정해 가격을 결정한다. 정적 보너스 한 번 지급으로 끝내지 않고 구독 기간에 재사용 가능한 콘텐츠와 지속 업데이트를 제공할 운영 계획이 필요하며 주기·분량·예산은 공개 전 확정한다.

산정 예시는 **가정**으로 일 사용자 D=1,000·하루 2회 실행·실행당 저장 5회·30일이면 저장 요청 300,000회다. 요청당 읽기 2/쓰기 2라고 가정할 경우 각각 600,000건이며 시작 시 조회·재시도·정산 중복 자료·인덱스/네트워크·삭제/백업은 별도다. 실제 고객 수나 확정 DB 구조/요금을 의미하지 않는다. 요청/스냅샷 크기·캐시·트랜잭션 재시도·자료 정리 정책을 측정해 공식 지역/에디션 요금에 대입한다. [Firestore 과금 항목](https://firebase.google.com/docs/firestore/pricing).

특정 원화 월요금·총비용·환율·수수료율을 확정하지 않는다. 공식 가격표의 포함 사용량만으로 '운영비가 전혀 없다'고 보장하지 않는다. Functions 운영 배포에는 과금 플랜이 필요할 수 있으며 사용자 월 예산·알림·최대 인스턴스/쿼터를 사전 결정한다. 예산 알림은 자동 과금 상한 보장이 아니다. [Firebase 공식 가격](https://firebase.google.com/pricing), [Functions 시작/과금 준비](https://firebase.google.com/docs/functions/get-started), [Functions 한도](https://firebase.google.com/docs/functions/quotas).

## 이후 확정할 중요 항목

출시 가격·국가·최소 OS·기체/스테이지 최종 수·밸런스·배포용 식별자·브랜드/자산 가용성·지원 연락처·개인정보처리자·보관 예외·월 운영 예산은 아직 미정이다. 계획 단계의 예시 값을 콘솔/프로덕션 설정으로 넘기지 않는다. 중요한 선택은 해당 단계에 한정해 확인하고 독립적인 로컬 게임 개발은 외부 콘솔 준비와 분리한다.
