# AI 문맥과 Git 제외

.gitignore는 Git 추적 제외입니다. 이미 추적된 파일을 해제하거나 AI·셸 접근을 차단하지 않습니다. 현재 저장소는 커밋·추적 파일이 없는 새 로컬 저장소이며, 검사 도구는 민감한 이름의 이미 추적된 파일이 있으면 본문을 읽지 않고 실패합니다.

## 도구별 준비

- Codex: .codex/config.toml에 :workspace를 확장한 monorepo-local 제한 프로필을 준비했습니다. 기본 보호를 유지하고 환경 파일·키·실제 데이터·로그·캡처 경로에 deny를 추가합니다. 권한·모델·승인 모드를 확대하지 않습니다.
- 현재 세션은 관리형 legacy sandbox_mode를 사용합니다. 새 프로필의 실제 적용을 확인한 상태가 아닙니다. 설정을 생성했다고 현재 세션의 파일 읽기 차단까지 완료됐다고 표시하지 않습니다.
- 새 세션에서도 legacy sandbox_mode/--sandbox 또는 관리 정책이 있으면 프로필이 적용되지 않을 수 있습니다. 기존 보안 설정을 삭제하거나 완화해 우회하지 말고 관리 설정과 호환성을 확인해야 합니다.
- Claude Code: .claude/settings.json에 프로젝트 경로 기준 Read/Edit deny를 추가했습니다. 임의의 Node/Python 하위 프로세스나 일부 IDE 전송까지 이 규칙만으로 모두 막는 것은 아닙니다. 실행 환경에서 실제 적용은 미확인입니다.
- 3단계에서 제안한 저장소 밖 ~/.app-secrets/ 경로도 Codex/Claude deny 준비 설정에 추가했습니다. 실제 비밀 폴더를 만들거나 열지 않았고 현재 관리 세션에서 차단을 확인한 것은 아닙니다.
- Codex/Claude 지침은 AGENTS.md를 공유합니다. 비밀 파일을 열거나 선택·첨부하지 않고 작업 명령에 자격증명을 넣거나 환경 전체를 출력하지 않습니다. .codexignore·.claudeignore를 강제 보안 경계라고 사용하지 않습니다.

## 실제 비밀을 다루기 전

실제 비밀·운영 데이터·개인 사진·민감 캡처는 이 저장소에 두지 않습니다. 테스트는 가상 데이터만 사용합니다. 서명/로그인·결제 식별자는 앱별로 분리하고 키는 AI 작업 범위 밖의 별도 저장 위치에서 사용자가 관리합니다. 파일 제외로 외부 MCP·브라우저·대화에 첨부한 자료까지 보호할 수는 없습니다.

재시작 후 가상 canary 파일로 직접 읽기와 하위 프로세스 접근 차단을 각각 확인하기 전에는 실제 민감자료를 넣지 않습니다. 현재 canary를 통한 OS 차단 검사는 미실행입니다. glob 차단은 프로세스 시작 시 기존 경로를 기준으로 확장되므로 새 파일을 만든 뒤에도 적용 상태를 다시 확인해야 합니다.

이 제한은 [Codex 권한 문서](https://learn.chatgpt.com/docs/permissions)와 [Claude Code 권한 문서](https://code.claude.com/docs/en/permissions)에 근거합니다.
